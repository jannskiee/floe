# CI lanes

Job names are the `name:` fields in .github/workflows/ci.yml; verify against the file when it changes. Every lane below is a `needs` of `CI green`, so any of them failing blocks the merge. `Skill test suites` joined the gate on 2026-10-13 and runs on every PR, whatever it touched, because some of its suites read product files. On a PR that touches only docs/ and .claude/skills/ every heavy job skips and `CI green` waits for that job alone: about three minutes (its median run was 152 s; measured on `main` at 2a6e273, `Repo guardrails` was done at 10:10:37 and `Skill test suites` at 10:13:00).

`Repo guardrails` (the peer-data consumer map, then the docs pre-flight, `docs-check.mjs all`) runs on every PR whatever it touched, docs-only and skills-only included, and is in the gate. The docs pre-flight reads more than `docs/`: a changed server default, or a floe.one/docs URL that names no page in Go, TypeScript, a workflow, .github Markdown or README.md, SELF_HOSTING.md, CONTRIBUTING.md, DESKTOP.md or SECURITY.md, fails it on a PR that touched no docs. It does not read the docs links of desktop/README.md, unraid/README.md or CLAUDE.md, so check those by hand. So run `node .claude/skills/docs-verify/scripts/docs-check.mjs all` locally on every lane, before the row for what you touched.

Commands are for the PowerShell tool from the repo root, with two exceptions: the `Go formatting` check in the notes is for the Bash tool, and so is every `gh ... --jq '<expression>'` whose expression has a space in it (from PowerShell gh answers "accepts at most 1 arg(s)"). pnpm is not on PATH here; `corepack pnpm` is, and it must run from inside client/ (the root has no packageManager pin, so from the root corepack runs pnpm 11.7.0, which refuses client's 11.1.2 pin).

Notes:

- A rename between docs/ and a code path always classifies as code (`--no-renames` in the classifier).
- `Repo guardrails` runs two scripts, not `*.test.mjs` files, so `Skill test suites` never covers them. Run check-consumers locally on any PR that touches a file the consumer map names or a peer-field token, and `node .claude/skills/docs-verify/scripts/docs-check.mjs all` on every PR, whatever it touched: the gate does.
- A `workflow_dispatch` or push event is always the full suite, whatever it touched.
- `Go formatting` runs `gofmt -l` over every tracked `.go` file. The local check, from the Bash tool at the repo root with your Go changes staged: `git ls-files '*.go' | while IFS= read -r f; do MSYS_NO_PATHCONV=1 git show ":$f" | gofmt -l | grep -q . && echo "$f"; done` must print nothing; any path it prints needs `gofmt -w`. It reads the index, so unstaged edits are not checked, and it works in a `core.autocrlf=true` checkout, where a plain `gofmt -l` over the working tree lists every file, formatted or not.
- CI runs Go 1.27 (the setup-go lines in ci.yml) and this machine's own `go` is older, so the Go rows above test a different toolchain from CI's. Prefix them with `$env:GOTOOLCHAIN='go1.27.2'` (in Bash, `GOTOOLCHAIN=go1.27.2`) to match; CI takes the newest 1.27 patch (`check-latest`), which was 1.27.2 on 2026-10-16, so name a newer one once it ships. That does not switch a bare `gofmt`, and Go 1.27 changed a column-alignment rule, so a file the older gofmt passes can fail `Go formatting`: run the check above with `"$(GOTOOLCHAIN=go1.27.2 go env GOROOT)/bin/gofmt"` in place of `gofmt` (on 2026-10-16 both printed nothing for all 226 tracked files).
- `E2E` and `Back-compat` upload a Playwright evidence artifact on every non-canceled run; download it before re-running, a rerun overwrites it.
- The rows that start with `Push-Location` assume it worked. In the PowerShell tool a failed `Push-Location` or `Set-Location` (a mistyped path, a clone that is not there) does not stop the chain: everything after it runs in the folder the session started in. Check the path first when the clone is not the session's own folder, and give every git command there `git -C <absolute path>`.
- `corepack pnpm build` (and `next dev`) rewrites the tracked `client/next-env.d.ts`. Restore it with `git checkout -- client/next-env.d.ts` before staging anything under client/.
- A red check outside the gate shows on the PR as `mergeStateStatus` `UNSTABLE`, and GitHub merges an `UNSTABLE` PR. No ci.yml job is outside the gate today (`Skill test suites` joined it on 2026-10-13); a check from another app, such as the Mintlify preview, still can be. references/blocked-pr.md item 4.
