# CI lanes

Job names are the `name:` fields in .github/workflows/ci.yml; verify against the file when it changes. Every lane below is a `needs` of `CI green`, so any of them failing blocks the merge, with one exception: `Skill test suites` soaks outside the gate (visible, non-blocking) until a few runs have shown it hermetic, so a red there never blocks a merge but still needs an explanation in the PR. `Repo guardrails` (the peer-data consumer map) runs on every PR whatever it touched, docs-only and skills-only included, and is in the gate. Commands are for the PowerShell tool from the repo root. pnpm is not on PATH here; `corepack pnpm` is, and it must run from inside client/ (the root has no packageManager pin, so from the root corepack runs pnpm 11.7.0, which refuses client's 11.1.2 pin).

| ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |

| .claude/skills/\*\* only                                                                                                        | `Repo guardrails` (in the gate) and `Skill test suites` (windows-latest, outside the gate); every heavy job skips. | client/\*\*                                                                                                                     | `Build & Lint` (Node 22, pnpm)                                                                                   | `Push-Location client; corepack pnpm install --frozen-lockfile; corepack pnpm lint; corepack pnpm test; $env:NEXT_PUBLIC_SOCKET_URL='https://api.floe.one'; corepack pnpm build; node scripts/check-titles.mjs; Pop-Location` (the install is mandatory after any branch switch) | `E2E (browser + CLI interop, <os>)` x3, `Back-compat (HEAD vs latest release)`, `Docker (self-hosting stack)` |
| server/\*\*                                                                                                                     | `Server (Node.js)` (Node 20)                                                                                     | `npm --prefix server ci; npm --prefix server test` (local Node is 22; CI tests on 20)                                                                                                                                                                                            | `E2E` x3, `Back-compat`, `Docker (self-hosting stack)`                                                        |
| cli/\*\*                                                                                                                        | `CLI (Go, <os>)` x3 (Go 1.25), plus `Desktop (Wails, windows-latest)` because the desktop app imports cli/engine | `Push-Location cli; go vet ./...; go test -count=1 ./...; go build ./cmd/floe; Pop-Location`                                                                                                                                                                                     | the other two OSes, `E2E` x3, `Back-compat`                                                                   |
| desktop/\*\*                                                                                                                    | `Desktop (Wails, windows-latest)`                                                                                | `Push-Location desktop/frontend; npm ci; npm test; npm run build; Pop-Location; Push-Location desktop; go vet ./...; go test -count=1 ./...; Pop-Location` (frontend build first, always: main.go embeds frontend/dist)                                                          | `wails build -nsis`, NSIS installer, `pack.ps1` MSIX packaging smoke                                          |

| anything else (README.md, CONTRIBUTING.md, SELF_HOSTING.md, DESKTOP.md, .claude/** outside .claude/skills/, docker-compose.yml, unraid/**, coturn/\*\*) | full suite (the classifier is negation-based: not under docs/ or .claude/skills/ means code)                                        | `docs-check.mjs` for markdown; otherwise nothing runs on these files locally                                                                                                                                                                                                     | everything                                                                                                    |

Notes:

- A rename between docs/ and a code path always classifies as code (`--no-renames` in the classifier).
- `Repo guardrails` is a script, not a `*.test.mjs`, so `Skill test suites` never covers it; run check-consumers locally on any PR that touches a file the consumer map names or a peer-field token.
- A `workflow_dispatch` or push event is always the full suite, whatever it touched.
- `E2E` and `Back-compat` upload a Playwright evidence artifact on every non-canceled run; download it before re-running, a rerun overwrites it.
