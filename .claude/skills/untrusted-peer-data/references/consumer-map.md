# Consumer map

Every place a value the remote peer chose is read, and what that place does to it. Built by reading the code after the 2026-08-28 hardening (fix/peer-display-safety); the treatment column describes that code, not an intention.

## Parse contract

scripts/check-consumers.mjs reads only the table under `## Map`. Its header must be exactly `| Field | File | Anchor | Sink | Treatment | Peer? |`.

- File: repo-relative, forward slashes, in backticks.
- Anchor: one string that exists verbatim in the file (a function, const, struct field, or event-name string), never a line number. Prefer the definition form (`func name(`, `function name(`, `func (a *App) name(`) for a function anchor, so the row cannot silently pin itself to a call site or to a longer identifier. The checker fails the row when the text is gone and warns when it matches only inside a longer identifier.
- Peer?: `yes` when the value came from the other machine; `no` when the same identifier holds a local value (File.name from the picker, totalBytes from /api/stats, the sum of bytes actually received); `pending` (with the follow-up named) while the treatment is still missing.
- One row per (field, file, anchor). A file earns a row by matching a FIELDS token in the checker (or by being listed in TOKEN_FREE); every sink inside it is mapped by hand.
- Test files (`_test.go`, `.test.ts`, `e2e/`) never get rows: the checker warns on them on purpose, and a new hostile test adds to that warning count by design. Two exceptions: a `no` row for token noise, a test that matches a token without touching the wire (a Sentry tag named `DOMException.code`), so the warning count keeps meaning "a test names a peer field"; and a `test` row for a DV-FUZZ harness that the build plan requires mapped, which records which decoders it drives and that it renders, logs and stores nothing.
- No pipes inside a cell.
