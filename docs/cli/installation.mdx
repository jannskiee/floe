This page installs `floe`, Floe's command-line client, on macOS, Windows, or Linux and confirms that it runs. It is for anyone who wants to send or receive from a terminal or a script. `floe` is a single self-contained binary with no runtime dependencies.

If you would rather have a window than a terminal, [Floe Desktop](/desktop/installation) runs on
this same transfer engine, so the two interoperate. It is Windows only; on macOS and Linux this
CLI and the [web app](/web-app/sending) are the options.

## Package managers

The fastest way to install `floe`. A package manager install is also updated with that tool's
standard upgrade command.

<Tabs>
  <Tab title="macOS">
    ```bash Terminal
    brew install --cask jannskiee/tap/floe
    ```

    Update: `brew upgrade floe`

    First run: if macOS blocks the binary (Gatekeeper), right-click the `floe` binary in Finder
    and choose Open, or run `xattr -dr com.apple.quarantine $(which floe)`.
  </Tab>
  <Tab title="Windows (winget)">
    ```powershell Terminal
    winget install jannskiee.floe
    ```

    Update: `winget upgrade jannskiee.floe`

    Winget is built into Windows 10/11. The package is available after each release once
    Microsoft's automated PR review completes (usually a few hours after the tag).
  </Tab>
  <Tab title="Windows (scoop)">
    ```powershell Terminal
    scoop bucket add jannskiee https://github.com/jannskiee/scoop-bucket
    scoop install floe
    ```

    Update: `scoop update floe`

    [Scoop](https://scoop.sh) can be installed with `irm get.scoop.sh | iex`.
  </Tab>
</Tabs>

## One-line installer

Works on macOS, Linux, and Windows without a package manager. Re-running the script
upgrades an existing install in place.

<Tabs>
  <Tab title="macOS / Linux">
    ```bash Terminal
    curl -fsSL https://floe.one/install.sh | sh
    ```

    To install a specific version, using any `vX.Y.Z` tag from the
    [releases page](https://github.com/jannskiee/floe/releases):
    ```bash Terminal
    curl -fsSL https://floe.one/install.sh | FLOE_VERSION=vX.Y.Z sh
    ```

    The script detects your OS and architecture (64-bit Intel or ARM), downloads the matching archive, checks its SHA-256 against the release's `checksums.txt`, and installs `floe` to `/usr/local/bin`, asking for your `sudo` password when that directory is not writable.
    Without `sudo` it installs to `~/.local/bin` instead, and says so if that directory is not on your `PATH`.
    If the machine has neither `sha256sum` nor `shasum`, or the release lists no checksum for the archive, the script prints a warning and installs without the check.
  </Tab>
  <Tab title="Windows (PowerShell)">
    ```powershell Terminal
    irm https://floe.one/install.ps1 | iex
    ```

    To install a specific version, using any `vX.Y.Z` tag from the
    [releases page](https://github.com/jannskiee/floe/releases):
    ```powershell Terminal
    $env:FLOE_VERSION = "vX.Y.Z"; irm https://floe.one/install.ps1 | iex
    ```

    The script downloads the `.zip` for your architecture (x64 or ARM64), checks its SHA-256 against the release's `checksums.txt`, installs `floe.exe` to `%LOCALAPPDATA%\Programs\floe`, and adds that directory to your user `PATH`.
    It asks for no administrator rights. If the release lists no checksum for the archive, the script prints a warning and installs without the check.
    Open a new terminal after running it.
  </Tab>
</Tabs>

## Go install

If you have Go 1.26 or later installed:

```bash Terminal
go install github.com/jannskiee/floe/cli/cmd/floe@latest
```

Go writes the binary to `$(go env GOPATH)/bin` (or `$(go env GOBIN)`), which is not on your
`PATH` on a default Go setup. Add that directory to your `PATH` before running `floe`. The
package managers and the install script above handle this for you.

<Warning>
  `go install` does not give you a release build. `cli` is a nested Go module and the
  repository carries no `cli/vX.Y.Z` tags, so `@latest` resolves to the current tip of `main`
  as a pseudo-version rather than to the newest release. The version string is stamped in at
  release time, so a binary built this way reports `floe dev`, and `floe update` stops with `Cannot update a dev build.`
  Use a package manager or the install script if you want a released build with working self-update.
</Warning>

## Verify the install

```bash Terminal
floe version
```

Expected output:

```text Output
floe 1.x.x
Docs: https://www.floe.one/docs
```

If the version you installed is not the newest release, a third line follows:

```text Output
Update available: v1.x.x  run `floe update` to upgrade
```

Set `FLOE_NO_UPDATE_CHECK=1` to silence it. See [`floe version`](/cli/version) for what that check does.
A binary from `go install` or built from source prints `floe dev` instead of a version number.

## Verify the checksum (manual download)

If you downloaded an archive directly from the [GitHub Releases page](https://github.com/jannskiee/floe/releases),
each release includes a `checksums.txt` file. To verify, run this in the directory that holds the archive:

```bash Terminal
# Download checksums
curl -LO "https://github.com/jannskiee/floe/releases/download/vX.Y.Z/checksums.txt"

# Verify (macOS)
shasum -a 256 --check --ignore-missing checksums.txt

# Verify (Linux)
sha256sum --check --ignore-missing checksums.txt
```

On Windows, `Get-FileHash <archive> -Algorithm SHA256` in PowerShell prints the hash to compare with the archive's line in `checksums.txt`.

## Update

For package manager installs, use the standard upgrade command (`brew upgrade floe`,
`winget upgrade jannskiee.floe`, `scoop update floe`).

For script or manual installs, run:

```bash Terminal
floe update
```

See [Update the CLI](/cli/update) for details.

## Build from source

Requires Go 1.26 or later.

```bash Terminal
git clone https://github.com/jannskiee/floe.git
cd floe/cli
go build ./cmd/floe
```

Move the resulting `floe` binary to a directory on your `PATH`. On macOS and Linux,
`/usr/local/bin` is the usual choice, but it is root-owned on a stock system, so the move
needs elevation: `sudo mv floe /usr/local/bin/`. A user-owned directory such as
`~/.local/bin` works without `sudo`, as long as it is on your `PATH`.

Like a `go install` build, a binary compiled this way reports `floe dev` and cannot update
itself.

## If something goes wrong {#if-something-goes-wrong}

- `floe` is not found after installing: open a new terminal, which reads the changed `PATH`, and
  check that the install directory is on it. See [`floe` is not found after installing](/troubleshooting#floe-is-not-found-after-installing).
- `floe update` prints `Cannot update a dev build.`: the binary came from `go install` or a source
  build. See [`Cannot update a dev build.`](/troubleshooting#cannot-update-a-dev-build).
- `floe update` prints `installed via homebrew`, `scoop` or `winget`: a package manager owns the
  binary, so use its upgrade command. See
  [`installed via homebrew`](/troubleshooting#installed-via-homebrew-run-brew-upgrade-floe-to-update).
