You are going to send a file and watch it arrive. The quickest way to see it work is to send to
yourself, in two tabs, so nothing depends on anyone else being ready.

<Steps>
  <Step title="Open Floe and pick a file">
    Go to [floe.one](https://floe.one) and drop a file onto the card, or click it to browse.
  </Step>
  <Step title="Create the link">
    Click **Create secure link**. Floe shows a link with **Copy** and **Show QR** under it. Click
    **Copy**.
  </Step>
  <Step title="Open the link in a second tab">
    Paste the link into a new tab. In real use this is where you would send the link to someone, or
    have them scan the QR code with their phone.
  </Step>
  <Step title="Watch it arrive">
    The transfer starts on its own, about 2 seconds after the two tabs connect. When the file
    lands, a download button appears on its row in the second tab. Click it to save.
  </Step>
</Steps>

## What just happened

Your two tabs met in a [room](/glossary#room) on Floe's [server](/glossary#signaling-server), which
only introduces them. Then they connected **directly**. The file went from one tab to the other
without passing through any server. That is why there is no upload to wait for, and why Floe sets no
size limit on a [direct connection](/glossary#direct-connection).

The [badge](/glossary#badge) at the top of the card said **Direct** once that path was open. On a
network that blocks direct connections it would have said **Relay** instead. The file would then have
traveled through an encrypted [relay](/glossary#relay) that cannot read it, with a 2 GB cap.

Before the second tab offered that download button, it checked the file. It compared the size, and a
fingerprint of the contents called its [SHA-256](/glossary#sha-256), with what the first tab sent. The
green check mark in front of "1 file received" is that check passing (the
[SHA-256 matched](/glossary#sha-256-matched) mark).

To read more:

- [How a transfer works](/how-it-works/signaling), and [File size limits](/how-it-works/2gb-limit) for
  the cap.
- [File checks](/how-it-works/file-checks), for what the SHA-256 check proves.
- [Security and privacy](/security-privacy), for what each part of Floe can and cannot see.

## The same thing from the desktop app or the terminal

Both send to and receive from the browser, and each other. Both also send folders and write what
they receive straight to disk. They differ from the browser in smaller ways too, and
[Which Floe to use](/choosing-floe) lists them.

### From the terminal

Install the `floe` [CLI](/glossary#cli), the command you type in a terminal. Pick your system below.
[Installation](/cli/installation) has the other ways to install it.

<Tabs>
  <Tab title="macOS">
    ```bash Terminal
    brew install --cask jannskiee/tap/floe
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell Terminal
    winget install jannskiee.floe
    ```
  </Tab>
  <Tab title="Linux">
    ```bash Terminal
    curl -fsSL https://floe.one/install.sh | sh
    ```
  </Tab>
</Tabs>

Then send:

```bash Terminal
floe send photo.jpg
```

`floe send` prints a [room code](/glossary#room-code), three words, and a link, and either one
works. The receiving side runs `floe receive olive-tiger-castle` with the code that was printed, or
pastes the code or the link into Floe Desktop's **Receive** tab, or opens the link in a browser.

### From Floe Desktop

Install Floe Desktop from the Microsoft Store, or from a terminal:

```powershell PowerShell
winget install --id 9NBQ8ZQ1065L --source msstore
```

Drop a file on the window and click **Send 1 item**. Floe shows a room code, a
[share link](/glossary#share-link), and a **Show QR** button, and any of the three gets the other
person in.

## Any Floe can talk to any other {#cross-platform-transfers}

Every pairing works, in both directions:

| Sender | Receiver | How the receiver joins |
|--------|----------|------------------------|
| Browser | Browser | Opens the link or scans the QR code |
| Browser | Desktop | Pastes the link into the Receive tab |
| Browser | CLI | `floe receive "<link>"` |
| Desktop | Browser | Opens the link or scans the QR code |
| Desktop | Desktop | Pastes the code or the link into the Receive tab |
| Desktop | CLI | `floe receive <code>` or `floe receive "<link>"` |
| CLI | Browser | Opens the link or scans the QR code |
| CLI | Desktop | Pastes the code or the link into the Receive tab |
| CLI | CLI | `floe receive <code>` or `floe receive "<link>"` |

A browser recipient always needs the link, because the web app has no field for a room code. When
you do not know what the other person will use, share the link. See
[Mixing them](/choosing-floe#mixing-them).

A [request link](/glossary#request-link) is the one transfer that starts
from the receiving side. Floe Desktop makes the link and receives, and the sender opens it in a
browser or runs `floe send <files> --to "<link>"`.

- To make one, see [Request links](/desktop/request-links).
- If someone sent you one, see [Sending through a request link](/web-app/request-links).

Folders are the other difference. The CLI and the desktop app send them and rebuild the structure
on arrival. In the browser, the Send page at floe.one cannot send a folder, and the page a request
link opens can. A browser that receives two or more files offers **Download ZIP**, which rebuilds
the folders inside the archive. Saving files one at a time flattens them.

## If something goes wrong {#next}

- The second tab shows "Link Invalid": the pasted link was cut short, or the link is already open
  in another tab. See [Troubleshooting](/troubleshooting#link-invalid).
- The second tab says "The sender is not connected": the first tab was closed or reloaded. See
  [Troubleshooting](/troubleshooting#the-sender-is-not-connected).
- "Connection failed. Ask the sender to try again." with a real recipient: the two networks could
  not reach each other. See
  [Troubleshooting](/troubleshooting#could-not-connect-ask-the-sender-to-enable-network-relay-and-try-again).
