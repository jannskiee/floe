Use the browser unless you need folders, a place on disk, or a script. There are three Floes: the
web app, Floe Desktop and the `floe` [CLI](/glossary#cli), a command you type in a terminal. Any of
them sends to any other, so the choice is about convenience rather than compatibility.

## Pick by what you are doing

**Sending one file to someone who has never heard of Floe.** Use the browser. You send them a
link, they open it, and the transfer starts on its own. They install nothing and no part of the
exchange needs explaining.

**Getting files from someone who does not have Floe.** There are two ways, and neither asks them
to install anything:

1. They open floe.one, drop the files, and send you the link. You open it in any Floe.
2. You make a [request link](/glossary#request-link) in Floe Desktop and send it to them. They open
   it in a browser and pick their files. Once you accept, the files land in a folder on your PC. See
   [Request links](/desktop/request-links).

**Sending a folder.** Use Floe Desktop or the CLI. Both walk the folder for you, and Floe Desktop or
the CLI on the other side rebuilds the same structure. A browser on the other side rebuilds it only
inside **Download ZIP**. The Send page at floe.one has no folder picker, but it sends a folder you
drop on it. The page a request link opens takes folders too.

**Receiving something very large.** Use Floe Desktop or the CLI. Both write straight to disk as
the bytes arrive. A browser receiver keeps each file inside the browser until you save it, and how
much it can hold depends on the browser: see
[Known limitations](/how-it-works/known-limitations#a-browser-receiver-is-limited-by-what-the-browser-can-hold).

**Transferring from a machine with no screen.** Use the CLI. It is a single program file that needs
nothing else installed, released for macOS, Linux and Windows on Intel and ARM. For a script or a
CI job, see [In scripts and CI](/cli/flags#in-scripts).

**Sending regularly from Windows.** Use Floe Desktop. It keeps a local history of the last 50
transfers, remembers where you save things, and, on the build from GitHub, can put
**Send with Floe** in the File Explorer right-click menu.

## Feature by feature

### Sending and receiving {#sending-and-receiving}

| | Web app | Floe Desktop | CLI |
|---|---|---|---|
| Platforms | Any modern browser | Windows 10 or later, 64-bit Intel or AMD (x64), as most PCs are: [how to check](/desktop/installation#requirements) | macOS 13 or later, Windows, Linux, on Intel and ARM |
| Install | None | Microsoft Store or a download | A [package manager](/glossary#package-manager), the one-line script, or `go install` |
| Send files | Yes | Yes | Yes |
| Send a folder | By dropping it, or through a request link | Yes | Yes |
| Share a link | Yes | Yes | Yes |
| Share a [room code](/glossary#room-code) | No | Yes | Yes |
| Show a QR code | Yes | Yes | No |
| Join with a link | Yes | Yes | Yes |
| Join with a room code | No | Yes | Yes |
| Where received files go | Your browser's downloads, after the whole file has arrived in the browser | Straight to disk, in a folder you choose | Straight to disk, in `-o` or the current directory |
| Folder structure on arrival | Flattened when saved one at a time, rebuilt inside **Download ZIP** | Rebuilt | Rebuilt |
| Confirm before receiving | No, it starts on its own | Only for a request link, unless you turn on [Auto-accept](/glossary#auto-accept) for it | Yes, unless you pass `-y` |

### Request links and extras {#request-links-and-extras}

| | Web app | Floe Desktop | CLI |
|---|---|---|---|
| Make a request link, so someone can send to you | No | Yes | No |
| Send [through someone's request link](/web-app/request-links) | Yes, supported in current Chrome and Edge on a computer | No. It offers an **Open in browser** button for the link | Yes, `floe send --to` |
| Refuse the [relay](/glossary#relay) | Yes when sending, the [Network relay fallback](/glossary#network-relay-fallback) checkbox | No | Yes, `--no-relay` |
| Force the relay to hide your [IP address](/glossary#ip-address) | Only when sending through a request link | Yes, **Hide my IP address** | Yes, `--relay-only` |
| Send a typed note | No | Yes, as `message.txt` | No |
| Paste files or a screenshot | No | Yes, with `Ctrl` `V` | No |
| Transfer history | No | The last 50, stored on your device | No |
| File Explorer right-click entry | No | Yes, on the build from GitHub | No |
| Point at a [self-hosted](/glossary#self-hosted) server | Automatic, it is served by that instance | **Settings**, then **Server address** | `--server` or `FLOE_SERVER` |

The setting that forces the relay is **Hide my IP** on a request link's page and **Hide my IP
address** in Floe Desktop. See [Hide my IP](/glossary#hide-my-ip).

## What is the same everywhere

These are properties of the transfer itself, so they do not change with the client you pick.

- **Encryption.** Every transfer is [encrypted end to end](/glossary#encrypted-end-to-end) over a
  [WebRTC](/glossary#webrtc) [data channel](/glossary#data-channel). See
  [Encryption](/how-it-works/encryption).
- **No size limit from Floe on a [direct connection](/glossary#direct-connection)**, and a 2 GB cap
  when the connection is relayed. See [File size limits](/how-it-works/2gb-limit).
- **Every file is checked on arrival.** The receiver compares each file with the size the sender
  announced. When the sender provides one, it also compares the file's
  [SHA-256](/glossary#sha-256), a fingerprint of its contents. A file that does not match is
  discarded. See [File checks](/how-it-works/file-checks).
- **One receiver per transfer.** While one recipient is connected, a second one is turned away. See
  [How a transfer works](/how-it-works/signaling#a-room-holds-exactly-two-people).
- **The sender stays connected** for the whole transfer. Closing the tab, quitting the app, or
  stopping the process ends it.
- **Versions do not need to match.** Every release so far speaks the same version of the transfer
  protocol, so peers on different releases transfer normally. See
  [Protocol versioning](/reference/transfer-protocol#protocol-versioning). Request links are the
  exception: they need Floe Desktop 0.3.0 or later, a server that has them turned on, and, to send
  from the terminal, `floe` 1.11.0 or later.

## Mixing them

Every combination works, and neither side needs to know what the other is using. Whatever each
side runs, both join the same [room](/glossary#room) on
Floe's [server](/glossary#signaling-server), which introduces them.

The one asymmetry worth remembering: **a browser recipient needs the link.** There is no place
to type a room code in the web app, and a browser sender never makes one. Room codes are a desktop
and CLI feature in both directions. When you are not sure what the person on the other end will
use, share the link, because every client accepts it.

See the [cross-platform table](/quickstart#cross-platform-transfers) for how each pairing joins.
